# Active goal presentation and operation feedback

Calculator Apply Plan continues to commit through applyCalculatorPlan/saveGoalVersion into the existing goals table. App keeps its single live query and tolerance-evaluation context. Goals defaults to CurrentGoals, a read-only projection of activeGoal(goals, selectedDate). The overview retains todayProgress/weeklyStatistics with their existing date/week semantics. There is no calculatorAppliedGoal or personalGoal store. Calendar selection and effective-date precedence are unchanged.

CurrentGoals uses saved targets when present, retains genuine legacy ranges otherwise, and shows only enabled nutrients/exercise targets. Exact scoped calorie targets previously disappeared from nutritionTargets when combined with legacy macro ranges. resolvedGoal now supplies evaluationCalorieTarget as presentation-only context, without inventing macro targets or rewriting ranges. saveGoalVersion explicitly strips this field like evaluationToleranceEvents; database records, schema and backup format are unchanged. A target of1235 with50 kcal tolerance displays1235 in CurrentGoals and1185–1285 in the overview: these are the target and its acceptable range, not conflicting goal states.

Edit/Set goals mounts the existing GoalEditor. Save uses the existing version/date workflow and returns to the read-only view. Cancel discards the separate draft and returns without modifying records. External goal-version changes or calendar date changes return to read-only display. Unsaved drafts remain session UI state and can be restored by explicitly reopening Edit; they are never active goals. History stays in the existing More workflow.

The existing global Notice callback accepts an optional duration, retaining the5000 ms default for unrelated actions. Plan applied and Goals updated use2500 ms, fixed-position neutral theme styling and mobile safe-area/nav clearance. Repeated identical successes restart the timer; a new save attempt clears prior feedback. Failed saves only show the existing concise error. Calculator has no permanent success state or in-flow success paragraph, so the calculation-notes position is unaffected.

Each overview column independently uses its selected-day record count. No records renders a two-line journal invitation and a compact calorie/exercise target summary, without number placeholders, empty bars or reserved reading heights. The first sentence is slightly stronger than the secondary invitation. Empty states use content-driven sizing and naturally expand into the unchanged detailed UI once records exist. Enabled macro goals retain their full, unfilled rings and target ranges in the same three-column order as recorded days; empty tracks blend the current action and soft theme tokens for a clearer, muted stroke. No intake number or center text is rendered, and empty nutrient labels reserve no space for absent intake values. Disabled macros retain their fixed column position and Off label. Any real record, including partial/unknown or recorded zero, restores the existing detailed progress styling. Weekly-average labels and daily/weekly exercise target labels remain explicit. Empty days can have earlier weekly records; their presentation still stays compact, without changing weekly calculations. Only the overview conditional presentation changes; the editorial cover/calendar are untouched.

Validation covers Apply→CurrentGoals→overview→reload, target/range agreement, legacy mixed-range targets (including lower-clipped ranges), edit/save/cancel, no-goal state, failed saves following success,2500 ms timer and stable layout, independent empty/partial columns, weekly-average/daily targets, zero/missing values, history preservation and Chinese/English mobile/desktop layouts.
